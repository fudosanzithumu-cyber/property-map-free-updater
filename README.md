# Workを使わない無料更新

- `update.yml` を、更新専用の公開GitHubリポジトリの `.github/workflows/update.yml` に配置します。アプリ本体・物件・顧客データは公開しません。
- 標準のUbuntuランナーのみを使用。privateリポジトリでは実行しないガードがあります。キャッシュ・成果物の保存、有料取得サービス、AI APIを使いません。
- GitHub ActionsのSecretsに `PORTAL_UPDATE_URL`（アプリURL + `/api/portal-free-update`）と `PORTAL_UPDATE_TOKEN`（管理者が設定した専用キー）を登録します。キーはコード・ログ・URLクエリに置きません。
- Sitesのサービス認証が必要な場合は、Sitesの正規サービスアクセス用トークンを `SITES_SERVICE_TOKEN` Secretに登録します。これは更新専用キーとは別です。検証ではこのヘッダーが必要でした。トークンが無効になった場合は更新を止め、正規の認証情報を更新してください。
- 日本時間9:02・17:02に起動予定です。GitHubの混雑で遅延・実行漏れがあり得ます。公開リポジトリは60日活動がないと定期実行が停止するため、実行履歴を確認し、停止時は再有効化してください。
- 3ポータル×2市×4種別を1対象ずつ処理し、途中処理は同じ対象で続行。既存の更新ロック・全ページ検証・失敗時データ維持を使います。
- HOME'Sも直接取得のみです。掲載元に拒否された場合や必要な項目が読めない場合は失敗として記録し、Firecrawl等へ切り替えません。無料で全件取得できる保証はありません。
- GitHubの「Run workflow」で実行し、アプリの更新履歴と保存結果を確認してから、既存Work予約を停止します。新経路の確認前にWork予約を止めないでください。
- キーの停止・交換はアプリ側の `PORTAL_FREE_UPDATE_TOKEN` を削除・交換し、再公開して行います。専用キーは更新以外の操作権限を持ちません。
